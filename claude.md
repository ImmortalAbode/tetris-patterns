# Промпт для Claude Code — проект «Тетрис» с 9 паттернами проектирования

Скопируй и отправь Claude Code (в терминале, из папки будущего проекта).

---

Помоги мне реализовать учебный проект — игру Тетрис на C++17, курсовая работа
по дисциплине "Паттерны проектирования". Работаю на MacBook (Apple Silicon),
Visual Studio Code, сборка через CMake, компилятор — clang (Xcode Command Line
Tools). Графика — SFML (устанавливается через `brew install sfml`).

## Цель проекта

В приложении должны быть явно реализованы и продемонстрированы 9 паттернов
проектирования. Для каждого паттерна нужен отдельный, легко находимый в коде
класс/модуль и понятный комментарий, объясняющий, какой это паттерн и зачем
он тут. Это учебная работа — важна не только рабочая игра, но и чистая,
показательная реализация каждого паттерна по отдельности.

Список паттернов и их роль в проекте:

1. **Abstract Factory** — `ShapeAbstractFactory`: создаёт семейство объектов
   под визуальную тему игры (например, classic и neon), продукты — блок
   фигуры и стиль сетки поля.
2. **Singleton** — `GameBoard` и/или `ScoreManager`: единственный экземпляр
   игрового поля и/или менеджера счёта, глобальная точка доступа.
3. **Builder** — `GameReportBuilder`: пошаговая сборка отчёта об окончании
   игры (заголовок, статистика по фигурам, итоговый счёт), конкретные
   строители — TextReportBuilder, HtmlReportBuilder.
4. **Factory Method** — `PieceFactory::CreatePiece()`: виртуальный фабричный
   метод, переопределяемый в подклассах для разных игровых режимов
   (обычный / спринт / и т.п.).
5. **Prototype** — прототипы фигур (I, O, T, S, Z, J, L) клонируются при
   каждом спавне новой фигуры вместо создания с нуля.
6. **Adapter** — `InputAdapter`: приводит разные источники ввода (клавиатура,
   в перспективе — геймпад) к единому интерфейсу `IInputHandler`.
7. **Компоновщик (Composite)** — иерархия `GameObject` → `Block` (лист) и
   `Tetromino` / `Board` (составные объекты), единый интерфейс `Draw()` и
   `CheckCollision()`.
8. **Chain of Responsibility** — цепочка проверки хода:
   `WallCollisionHandler → FloorCollisionHandler → BlockCollisionHandler`.
9. **Command** — `MoveLeftCommand`, `MoveRightCommand`, `RotateCommand`,
   `DropCommand`, `MacroCommand`; с историей команд для undo (отмена
   последнего хода).

## Как работаем

Двигаемся строго по шагам, не пытайся сделать всё за один раз. После каждого
шага останавливайся, показывай, что получилось, и жди моего подтверждения,
прежде чем переходить к следующему. Если на каком-то шаге нужно принять
архитектурное решение (например, как именно организовать взаимодействие
между паттернами) — предложи варианты и спроси меня, а не решай molча.

### Шаг 0. Структура проекта и сборка
- Создай структуру каталогов проекта (`src/`, `include/`, `assets/`,
  `CMakeLists.txt`).
- Настрой `CMakeLists.txt` под clang на macOS с подключением SFML через
  `find_package`.
- Проверь, что "hello window" на SFML собирается и запускается (пустое окно).
- Настрой `.vscode/` (tasks.json, launch.json, c_cpp_properties.json), чтобы
  сборка и отладка работали прямо из VS Code через CMake Tools.

### Шаг 1. Базовая логика игры без паттернов
- Игровое поле (сетка), падение одной фигуры, управление (влево/вправо/
  вниз/поворот), проверка коллизий и удаление заполненных линий — максимально
  простой, "неправильной" реализацией. Это нужно, чтобы сначала увидеть
  рабочую игру, а потом рефакторить её под паттерны — так виднее, что именно
  каждый паттерн улучшает.

### Шаг 2. Порождающие паттерны
- Введи Abstract Factory для тем оформления.
- Сделай Singleton для игрового поля/менеджера счёта.
- Добавь Factory Method для создания фигур.
- Перепиши создание фигур на Prototype (клонирование вместо `new`).
- Объясни в комментариях, как эти четыре паттерна взаимодействуют друг с
  другом в твоей реализации (в методичках это описано — учти это).

### Шаг 3. Структурный паттерн
- Введи Adapter для ввода.
- Перепиши структуру "фигура из блоков" через Компоновщик.

### Шаг 4. Паттерны поведения
- Введи Chain of Responsibility для проверки коллизий при движении фигуры.
- Перепиши систему управления на Command, добавь историю команд и undo
  последнего хода (хотя бы один уровень отмены).

### Шаг 5. Builder и отчёт
- Добавь экран/лог окончания игры, собираемый через Builder (минимум два
  конкретных строителя — например, текстовый вывод в консоль и HTML-файл).

### Шаг 6. Полировка
- Проверь, что каждый из 9 паттернов легко найти в коде (отдельный файл или
  явно выделенный блок, комментарий с названием паттерна).
- Собери краткую сводную таблицу в README.md: паттерн → класс(ы) → файл.
- Если что-то из готового кода не запускается или ломается — почини.
